### Leçons techniques de la session
- **Heredoc python via exec = poison** : le JSON encode `\n` → vrai retour ligne qui casse les chaînes Python multi-lignes (unterminated string). Utiliser `chr(10)` ou écrire le script dans un fichier d'abord. Les apostrophes françaises (d'Amundi) cassent les chaînes simples → guillemets doubles ou triple quotes.
- **pkill -f <pattern> = suicide** : le pattern matche la propre ligne de commande du shell (le heredoc contient le pattern) → SIGTERM sur la commande courante. Utiliser `pgrep -f "pattern[l]"` (classe char) ou vérifier les PIDs avant kill.
- Le format JSON strict échoue sur etf-data.min.js (guillemets typographiques « ” » dans les noms) → **toujours loader via eval/Node** (c'est ce que fait le navigateur), jamais json.loads.
- prod = `/var/www/html` (nginx), propriétaire www-data → `sudo cp` ; backups systématiques type `.bak_audit2_20260919`.
- Cache-bust des fichiers modifiés obligatoire dans index.html (`?v=`) sinon l'utilisateur garde l'ancien code.
- Les erreurs de compilation Python dans les scripts de patch n'écrivent RIEN (fichier intact) → toujours vérifier par un comptage avant/après.
- `etf_quality_score.py --emit-scores` = pipeline de déploiement complet pour les scores (régénère, sudo cp live, bump cache-bust) → privilégier plutôt que patcher etf-scores.js à la main.

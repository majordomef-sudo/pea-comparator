## Debug tools — "rien ne se passe" au clic (09:24-09:43)

### Problème
- Malgré la refonte complète, Eric signale que cliquer sur les outils/simulateurs ne fait rien
- Le logo s'affiche, le HTML est chargé, mais les interactions JS ne fonctionnent pas

### Diagnostic
- `script.js` utilise `document.querySelectorAll('.tool-card-header').forEach(...)` pour attacher les event listeners
- Si le script s'exécute avant que le DOM soit complètement parsé, `querySelectorAll` retourne un NodeList vide → aucun event listener attaché
- Même en fin de body, des scripts lourds (etf-data.min.js 112 KB) peuvent retarder le parsing

### Fix appliqué (09:28)
- Ajout d'un **script inline d'event delegation** directement dans le HTML, exécuté via `DOMContentLoaded`
- Capture tous les clics sur `.tool-card-header` par délégation sur `document`
- Ne dépend pas du timing de chargement du DOM
- Alternative : wrapper le `script.js` entier dans `DOMContentLoaded` (non fait — trop risqué de modifier le fichier via heredoc)

### Statut
- Fix déployé sur `/var/www/html/index.html`
- En attente du test par Eric (Ctrl+F5 requis)
- Si toujours KO → demander les erreurs console (F12 → Console)

## Leçons supplémentaires
- ⚠️ **Event delegation > querySelectorAll direct** pour les sites avec gros scripts — plus robuste
- Toujours wraper l'init JS dans `DOMContentLoaded` quand les scripts sont lourds
- Demander la console navigateur (F12) systématiquement quand "rien ne fonctionne" — perte de temps à diagnostiquer à l'aveugle

### Problème suite refonte
- Eric a rebuild le site avec `rebuild.py` et redéployé, mais les simulateurs ne s'ouvraient toujours pas au clic
- Rien dans la console ni les onglets Network — le JS `script.min.js` n'était pas chargé

### Diagnostic
- **Cause #1** : `script.js` (4 lignes, loader) n'était pas copié dans `/var/www/html/` — le site chargeait l'ancien `script.js` qui n'injectait plus `script.min.js`
- **Cause #2** : `script.min.js` contenait un second IIFE (watchlist/modal) qui plantait avec `ReferenceError: ROWS is not defined` — le second bloc n'avait pas accès aux variables du premier IIFE
- **Cause #3** : `etf-data.min.js` définissait `const ETF_DATA = [...]` (pas en global) — `script.min.js` cherchait `window.PEA_ETFS` qui n'existait pas
- **Cause #4** : Les cartes simulateurs avaient `display: none` sur le corps mais aucun JS pour les ouvrir

### Fix appliqué (12:00-12:20)
1. **Copié `script.js`** dans `/var/www/html/` (loader existait pas)
2. **Supprimé le second IIFE** de `script.min.js` (watchlist/modal) qui plantait
3. **Exposé `window.PEA_ETFS`** dans `etf-data.min.js`
4. **Ajouté toggle** : clic sur l'en-tête ouvre/ferme la carte, première carte ouverte par défaut
5. **Déploiement** : `index.html`, `script.js`, `script.min.js` (via sudo)

### Résultat
- Les simulateurs s'ouvrent maintenant au clic — Eric confirme ✅
- Mais les **calculs ne s'affichent pas** — les résultats restent vides
- Problème suivant à investiguer : les fonctions de calcul ne s'exécutent pas ou n'écrivent pas les résultats

### Leçons du jour (suite)
- ⚠️ **Toujours copier TOUS les fichiers JS** (pas seulement HTML) — le loader est invisible mais critique
- Le second IIFE dans script.min.js peut planter silencieusement sans erreur visible en production
- Demander la console F12 systématiquement quand le diagnostic est en aveugle
- `const ETF_DATA` ≠ `window.PEA_ETFS` — ne pas confondre scope module et scope global
